# NEO CLASSIC SLOT — 開発運用方針

## 体制
- **ChatGPT（チャッピー）**: 企画・仕様管理の指令塔。方向性、仕様の矛盾チェック、デザイン素材制作、指示作成、技術判断。
- **Claude Code**: 実装担当。プログラム、リール配列・停止制御、テストと不具合修正、画像組み込み、報告。
- **ユーザー**: ゲームの面白さ・デザインの最終判断と、両者のメッセージの中継のみ。

ChatGPT と Claude Code は直接通信できない。ユーザーが報告・指示をそのまま転送する。

## 判断の原則
1. 技術的な判断（バグ修正、コード構造、テスト方法、素材管理など）は Claude Code が行う。
2. 技術的に合理的な解決策があれば、推奨案を選んで作業を進める。
3. 仕様に矛盾がある場合、ゲーム性を独断で大きく変えず、ChatGPT 向けに技術的な説明と推奨案を出す。
4. ユーザーに確認するのは、ゲーム性・デザイン・演出・重要な仕様変更など本人の判断が必要なものだけ。
5. 承認済みの仕様は、毎回許可を求めずに実装を進める。
6. ゲーム性の大幅変更、重要な仕様変更、既存データの削除は事前に確認する。
7. テストで不具合を見つけたら、可能な範囲で修正と再検証まで行う。

## 報告の形式
報告は毎回この形式にする（ユーザーがそのまま ChatGPT へ貼り付けられる文章で書く）。専門的な説明は最小限に。

```
【作業完了】
【テスト結果】成功・失敗・未検証を明記
【ChatGPTへの相談】必要な場合のみ。転送用の文章で
【ユーザーへの確認】本人の判断が必要な項目だけ。無ければ「ユーザーへの確認：なし」
【次の作業】
```

## プロジェクトの保護
- 作業対象は `neo-classic-slot/` のみ。
- 他のプロジェクト、特に「たけとサイの大冒険」（別ブランチ `claude/takenin-summer-game-em1re8`）は変更しない。

## 作業の基本
- 停止制御・配列を変えたら `node tools/verify.js`（全停止パターンの総当たり検証）を必ず通す。
- 設計資料: `docs/DESIGN.md`、素材一覧: `docs/ASSETS.md`、検討中の案: `docs/proposals/`。
